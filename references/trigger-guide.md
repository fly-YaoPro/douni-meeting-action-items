# 豆尼会议纪要模块｜同事使用说明

## 最省事的用法

在内部群或豆尼私聊里，@豆尼并附上会议资料即可。资料可以是飞书妙记/会议记录/会议纪要链接，也可以是录音视频、TXT/DOCX、外部转写文本，或一条包含这些资料的被引用消息。

默认会完成四件事：读取完整逐字稿、提取待办与 DDL、归档到会议知识库、把有效未完成事项接入每日提醒。

## 怎么说都可以

下面的话术只是示例，不是口令。豆尼会结合当前消息、被引用的原消息、附件和链接，由模型判断应该调用哪个 Skill。引用内容已经能说明这是会议资料时，直接说“这个收一下”“整理下，别放提醒里”也可以。

明确写出“会议、妙记、待办”等词时会走不耗 Token 的快速通道；没写固定词时走语义路由，不会因为少一个关键词退回普通问答。

## 常见说法

### 常规整理并加入提醒

- `@豆尼 整理一下这场会，待办接入提醒：<妙记链接>`
- `@豆尼 看看会上定了什么，谁负责、什么时候交：<会议链接>`
- `@豆尼 把这份周会纪要归档，未完成事项加到 DDL：<文档链接>`
- `@豆尼 复盘下这个妙记，提取客户要求和我们承诺的事：<妙记链接>`
- `@豆尼 把会后行动项落一下：<会议记录链接>`

### 只看客户要求

- `@豆尼 重点找客户提的要求、负责人和 DDL：<妙记链接>`
- `@豆尼 看下客户在会上让我们做什么：<会议链接>`

系统仍会保留完整归档，但回传卡片会优先呈现可执行待办。

### 只归档，不加入提醒

- `@豆尼 这次只归档，不用加入每日提醒：<妙记链接>`
- `@豆尼 仅总结一下，先别写入待办：<会议链接>`
- `@豆尼 存进会议知识库就行：<纪要文档链接>`

这类消息会生成归档文档和回传卡片，但提醒数为 0。

### 一次处理多份会议

- `@豆尼 把这两场会分别整理、归档并提待办：<链接1> <链接2>`

一条消息最多处理 5 个来源，每场会议单独回一张卡，避免任务混在一起。

### 引用飞书原消息

- 引用带会议链接的消息：`@豆尼 整理这场会，把未完成待办加入提醒`
- 引用内容已经明确是会议资料：`@豆尼 这个收一下，别放到提醒里`
- 引用带录音/视频的消息：`@豆尼 把这个附件转成妙记并整理待办`
- 引用带 TXT/DOCX 的消息：`@豆尼 读这份会议资料，只归档先不提醒`

引用后不必重新粘贴资料。若没有引用、原消息已撤回、遥师身份无权限或附件类型不支持，豆尼会直接说明怎么补充，不会停在“处理中”。

## 豆尼会回什么

回传 Card 2.0 包含：

- 提取待办、进入提醒、仅归档的数量；
- 会议概括；
- 每项待办的内容、执行人、DDL 和提醒状态；
- 下一次统一提醒时间，以及 DDL 前提醒说明；
- “打开存档文档”和“查看原会议”按钮。

## 哪些情况不会执行

- 只说“帮我看看”，当前消息和引用消息里也没有会议资料；
- 只说“整理会议”但既没有引用消息，也没有附链接、文件或会议原文；这时会提示补资料，不会启动模型；
- 普通业务 Wiki/Docx 链接只配“总结一下”“分析一下”，没有任何会议语义；
- 外部群中的客户或供应商消息。

这样做是为了避免把普通业务文档误当会议记录，也避免会议内容被发到外部群。

## 提醒规则

- 有明确 DDL：进入每日待办，并按 Daemon 当前配置触发统一提醒和 DDL 前提醒；
- 只有日期：按日期型 DDL 规则提醒；
- 无 DDL：作为长期事项保留，直到完成；
- 夜间触发的提醒：顺延至次日 10:00；
- 已完成或证据不足：只归档，不进入提醒。

统一提醒的具体时刻不写死在本 Skill 中，以豆尼控制台的 Daemon 调度设置为准。
